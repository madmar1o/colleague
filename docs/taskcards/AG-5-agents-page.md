1) Красный тест (коммит 1): `AgentCatalogTest` (3) — слияние двух уровней каталога
   (личный `~/.colleague/agents` + проектный `.colleague/agents`, проектный перекрывает по id,
   порядок по имени, отсутствующий уровень — не ошибка); `PageCatalogEventsTest` +2 —
   `PageCatalogEvents.agents()`: карточки страницы (встроенный «Колега по умолчанию» первым,
   `builtin: true`, `model` у каждой карточки, скрытые и `SUBAGENT` вне списка).
   Реализация: `agents/AgentCatalog`, `PageCatalogEvents.agents(...)`.
2) UI (коммит 2): `web/agents.html` — карточки агентов (аватар-буква, имя, описание, модель
   read-only; клик = `openAgent`); `AgentsPanel` (мост `bridgeReady/refresh/openAgent/openSettings`);
   `ColleagueView`: стартовая страница = агенты (при живом браузере), `openAgent` -> вкладка чата
   под агентом (модель агента или дефолт провайдера, текст таба = имя агента), стрелка «назад» ->
   страница агентов, шестерёнка -> страница провайдеров (`ChatPanel.setOnOpenSettings`,
   `setInitialAgent` — вкладка говорит под профилем с первого хода); `Contact` получил
   `agentName` (ключ сессии `providerId+model+agent`); авто-открытие чата на холодном старте
   убрано; пустой таб-фолбэк ведёт на агентов.
3) `ContactsPanel` — чистая страница настроек: мостовой кейс `openContact` удалён, чипы моделей
   в `contacts.html` больше не открывают чат (остались информационными); SWT-фолбэк без браузера
   сохраняет вход в чат выбором в дереве.

## Критерии приёмки
Вид при открытии — список агентов с карточкой «Колега по умолчанию»; клик по карточке открывает
чат-вкладку с именем агента в заголовке и профилем, выбранным с первого хода; шестерёнка из чата
открывает провайдеров/модели/MCP; стрелка «назад» возвращает к агентам. `AgentCatalogTest` 3 и
`PageCatalogEventsTest` 7 зелёные, `node --check` обеих страниц зелёный,
`mvnw -B clean verify` зелёный (EXIT=0).
