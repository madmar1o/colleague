# AGENTS.md — правила работы в этом репозитории

## Проект
- Плагин 1C:EDT (Java, Eclipse RCP/OSGi, Tycho), ID `com.mad.edt.colleague.*`.
- Целевая EDT: 2026.1 (p2 `https://edt.1c.ru/downloads/releases/ruby/2026.1/`), EE JavaSE-17.
- Полностью собственная оригинальная разработка: в коде, комментариях, документации,
  названиях, коммитах и артефактах не допускается упоминать чужие продукты и их
  внутреннее устройство. Никаких заимствований из чужих расширений/плагинов.

## С чего начать (новая задача / новый агент)
- Индекс всех задач плана с ветками и зависимостями: `docs/taskcards/INDEX.md` (main).
- Карточка конкретной задачи: `docs/taskcards/<ID>.md` — все карточки уже в `main`;
  описание feature-ветки, пока она жива, — `git notes show <ветка>`.
- Борд статусов: Qdrant `colleague_tasks`, payload.id задачи (`PP-*`); REST `http://127.0.0.1:6333`
  (команда в INDEX.md). Порядок вех: M21 -> M27, зависимости — в карточке.
- Полный текст плана и обоснований — в рабочей папке ВНЕ репозитория (PARITY-PLAN.md,
  RESEARCH-*.md); в репозиторий их содержание переносить только собственными словами.

## Ветки и архивы (после чистки 2026-11-22)
- Ствол один — `main`, он же опубликован в `origin/main`. Feature-ветки закрытых задач
  удалены: 50 веток, из них 46 полные предки `main` (`merge-base --is-ancestor`).
- Новая задача = `feature/<id>` от `main`, слияние `git merge --no-ff feature/<id>`,
  после слияния ветка удаляется (`git branch -d`). Работа ведётся в основном worktree;
  отдельных каталогов `worktrees/` в рабочей папке больше нет (`git worktree list` —
  только репозиторий).
- Не влитое в ствол сохранено аннотированными тегами (локально, на GitHub не пушились):
  `archive/pp-f6-hook-registry` — код хук-реестра PP-F6, отложенного по спеке 0005;
  `archive/milestone-m25`, `archive/milestone-m26`, `archive/milestone-m27` — вершины
  архивных вех (содержимое m26 и m27 целиком в `main`, в уникальных коммитах только
  слияния).

## Конвенции
- Не менять `Bundle-Version` (`x.y.z.qualifier`) и qualifier-формат `'v'yyyyMMddHHmm`.
- Новый бандл = MANIFEST.MF + build.properties + plugin.properties + pom.xml + запись в `bundles/pom.xml`, feature.xml и (если надо) category.xml.
- Заголовки MANIFEST в том же порядке, что в существующих бандлах.
- Пакеты: `com.mad.edt.colleague.<область>`. Публичный API — в `Export-Package`, остальное `x-internal:=true`.
- Require-Bundle/Import-Package — с версиями-диапазонами; версии сверять с content.xml целевого p2-репозитория, не выдумывать.
- Коммиты: `<type>: <описание>` (chore|feat|fix|docs|refactor|test), ветка `main`.
- Секреты (API-ключи провайдеров) не коммитить; конфиг LLM — Preferences/Secure storage.

## Проверки
- Разово после свежего клона: `git config core.hooksPath .githooks` — включает гейт
  формата коммита (`commit-msg`) и фоновый пересчёт SonarQube после git-событий.
  Git не переносит эту настройку при клонировании; без неё хуки в `.githooks/` не активны.
- Перед пушем: `.\mvnw.cmd clean verify` обязан проходить.
- Изменения MANIFEST/feature — пересобирать, не «на глаз».

## Запреты
- Не менять `targets/*.target` без веской причины (это контракт целевой платформы).
- Не обновлять Tycho/EDT-версии «за компанию» с основной задачей.
- В репозиторий не попадает ничего, где упоминаются названия чужих AI-продуктов,
  их бандлы, форматы или внутренняя статистика — это независимая реализация.
